# Bot update: five features

These changes belong to the Python bot in `E:\BotCodex\RainDealsBott`.
They do not deploy or update the Cloudflare manager.

1. **Shared screen controller.** Existing card helpers share one registry and
   serialize rendering and state writes for each user/chat.
2. **Latest navigation wins.** Product/category, payment, order and Home
   navigation invalidate older handlers. Superseded handlers cannot repaint
   the card or overwrite the current input state through the shared helpers.
   A purchase already submitted still completes independently of navigation.
3. **Durable checkout confirmations.** Each confirmation has a unique token.
   A database claim blocks reusing that token, including across process restarts.
   Orders store a unique checkout key alongside the wallet/stock transaction.
   Supplier requests use a stable external reference. This is not a guarantee
   that a provider supports idempotency. Uncertain attempts are not retried
   automatically: check My Orders and reconcile with the supplier first.
4. **Order timeline.** My Orders → order → Order timeline. Admin order details
   have a timeline too. New purchases, customer information, delivery and
   refunds record events in their database transactions. Legacy orders show
   available creation, submission and audit timestamps; missing past events
   are not invented. Private assignment/note metadata stays out of customer views.
5. **Fulfillment queue.** Admin → Orders → Fulfillment queue. Filter all active,
   ready, waiting for information, Mine or Unassigned. High priority orders come
   first, then oldest. Open an order to take/release/reassign it, change priority,
   or add private notes. Remaining quantity excludes automatic deliveries.
   Telegram and manager manual completion reject orders assigned to another
   admin until explicitly reassigned. Manager completions also record team
   assignment/completion events in the timeline when its table is available.

## Deployment and checks

Normal application startup checks/adds the tables and columns through
`ensure_order_requirements_schema`. If the database user lacks DDL permission,
an administrator can apply
`migrations/20261105_checkout_and_order_workflow.sql` once first. Already-applied
ALTER statements should be skipped. No new secrets are required.

After deployment, open the product again to create a fresh confirmation.
Buttons generated by the previous version expire safely. A confirmation that
has already been claimed never becomes a fresh checkout through `/restart`.

Run the automated checks with:

```powershell
Set-Location E:\BotCodex\RainDealsBott
python -m unittest discover -s checks -p 'test_*.py' -v
```

Tests use isolated fixtures/SQLite with a MySQL syntax adapter; they do not
prove live TiDB concurrency, Telegram delivery or supplier behavior. Staging
checks should cover: rapid category → Home navigation; one low-value purchase
with a repeated confirmation; timeline visibility for a different buyer; and
assignment/partial delivery with two admins. These live checks are not run by
the automated suite.
